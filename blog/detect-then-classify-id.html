Pola Detect-Then-Classify

📅 Mei 2024 ⏱️ 8 menit baca 🏷️ Computer Vision · Architecture · PyTorch

Sebagian besar materi computer vision menyarankan pemodelan tunggal yang menyelesaikan seluruh alur kerja: mendeteksi lokasi objek SEKALIGUS menentukan klasifikasinya dalam satu siklus inferensi (forward pass). Arsitektur seperti YOLO, SSD, maupun Faster R-CNN beroperasi secara end-to-end untuk menghasilkan bounding box beserta label kategorinya.

Pada lingkungan production, pendekatan serba satu (end-to-end) belum tentu menjadi pilihan yang optimal. Berikut analisis tantangannya serta solusi arsitektur yang lebih efektif.

Tantangan Pemodelan End-to-End

Saat sistem dihadapkan pada ratusan kategori spesifik (fine-grained), tingkat kompleksitas kombinasi fitur melonjak pesat. Pemodelan YOLO tunggal yang ditargetkan untuk membedakan 200 varian produk (SKU) kerap menemui kendala teknis:

  • Ketidakseimbangan frekuensi data (Class Imbalance): Beberapa varian produk muncul jauh lebih dominan dibandingkan varian lainnya.
  • Tumpang tindih fitur visual (Feature Interference): Layer ekstraksi fitur pada detektor dioptimalkan untuk lokalisasi posisi, bukan untuk pembedaan kelas yang sangat serupa.
  • Keterbatasan alur pembaruan: Penambahan satu kategori baru mengharuskan pelatihan ulang (retrain) seluruh model secara utuh.
  • Kekakuan arsitektur deployment: Logika klasifikasi tidak dapat diperbarui secara terpisah dari komponen detektor utama.

Solusi: Pemisahan Deteksi dan Klasifikasi

Pola detect-then-classify membagi alur kerja ke dalam tahapan-tahapan yang independen:

  1. Tahap Deteksi (YOLO / EfficientDet): Memetakan lokasi seluruh objek dan menghasilkan bounding box. Model ini difokuskan pada pemisahan "objek vs latar belakang", sehingga prosesnya jauh lebih cepat dan stabil.
  2. Tahap Klasifikasi Kasar (Coarse Classification): Mengelompokkan tiap area potongan gambar (crop) ke dalam grup kategori umum (seperti "elektronik", "pakaian", atau "makanan") menggunakan model yang efisien dengan tingkat recall tinggi.
  3. Tahap Klasifikasi Halus (Fine Classification): Pada setiap grup, modul classifier khusus melakukan identifikasi item spesifik. Tiap modul hanya mengelola 20–50 kelas, sehingga jauh lebih efisien untuk dilatih dan dipelihara.

Keunggulan pada Lingkungan Production

1. Peningkatan Akurasi per Kelas

Modul classifier yang menangani 30 kelas secara khusus terbukti menghadirkan presisi yang lebih tinggi dibandingkan detektor tunggal yang memproses 200 kelas sekaligus. Kapasitas komputasi model difokuskan penuh pada diskriminasi fitur visual. Pada pipeline production saya, pendekatan bertahap ini meningkatkan F1-score per kelas sebesar 12–18% dibandingkan baseline YOLO end-to-end.

2. Kemudahan Pemeliharaan Modul (Maintainability)

Saat terjadi penambahan 5 SKU produk baru, pelatihan ulang hanya dilakukan pada modul classifier halus yang relevan, tanpa perlu melatih ulang detektor utama maupun modul classifier lainnya. Waktu pelatihan berkurang drastis dari durasi jam menjadi hitungan menit, sekaligus meminimalkan risiko gangguan sistem secara keseluruhan.

3. Fleksibilitas Deployment

Komponen detektor dapat di-deploy pada perangkat edge (menggunakan ONNX terkuantisasi), sementara modul klasifikasi halus beroperasi pada server apabila diperlukan. Penggantian arsitektur detektor (seperti dari YOLOv8 ke YOLO-NAS) juga dapat dilakukan tanpa mengubah logika klasifikasi.

4. Kemudahan Penelusuran Masalah (Debugging)

Apabila terjadi ketidaksesuaian hasil, lokasi kendala dapat teridentifikasi secara tepat: apakah disebabkan kegagalan lokalisasi objek, kesalahan pengelompokan kasar, atau penentuan kelas halus. Arsitektur bertingkat menyajikan metrik terukur untuk tiap tahap sehingga proses analisis masalah berlangsung efisien.

Pertimbangan Pertukaran Performa (Trade-offs)

  • Latensi eksekusi: Rantai eksekusi multi-model memerlukan beberapa kali forward pass. Namun melalui optimasi ONNX dan teknik batching, beban waktu tambahan umumnya berada di bawah 10ms sehingga tetap relevan untuk mayoritas kebutuhan industri.
  • Manajemen komponen: Diperlukan pengkelolaan alur antar-modul. Meski demikian, pemisahan peran ini justru menyederhanakan arsitektur sistem secara keseluruhan dibandingkan pengelolaan satu model besar yang kompleks.
  • Kebutuhan data latih: Setiap classifier membutuhkan dataset pelatihannya sendiri. Pengorganisasian data yang terstruktur mempermudah penyediaan dataset spesifik ini.

Kondisi Penggunaan Alternatif

  • Variasi kelas di bawah 20 jenis; pemodelan end-to-end umumnya sudah mencukupi.
  • Persyaratan latensi sangat ketat (< 5ms) yang tidak memungkinkan adanya beberapa tahap forward pass.
  • Pemisahan fitur visual tiap kelas sangat kontras dan tidak memerlukan diskriminasi tingkat lanjut.
  • Tahap awal pembuatan prototipe; pendekatan sederhana lebih disarankan sebelum menambah kompleksitas alur.

Sketsa Kode

# Pipeline detect-then-classify yang disederhanakan
import torch
from detector import YOLODetector
from classifiers import CoarseClassifier, FineClassifier

class StagedPipeline:
    def __init__(self):
        self.detector = YOLODetector("yolov8n.pt")
        self.coarse = CoarseClassifier("efficientnet_b0_coarse.pt")
        self.fine = {
            "electronics": FineClassifier("resnet18_electronics.pt"),
            "clothing": FineClassifier("resnet18_clothing.pt"),
            "food": FineClassifier("resnet18_food.pt"),
        }
    
    def __call__(self, image):
        crops = self.detector.detect(image)
        results = []
        for crop, bbox in crops:
            coarse_label = self.coarse.classify(crop)
            fine_label = self.fine[coarse_label].classify(crop)
            results.append({"bbox": bbox, "label": fine_label})
        return results

Kesimpulan

Pola detect-then-classify mengedepankan kepraktisan alur kerja. Meskipun sederhana, penerapannya pada lingkungan production terbukti unggul dalam hal kemudahan pemeliharaan dan keandalan akurasi data nyata. Membagi permasalahan ke dalam tahapan independen menjadikan sistem lebih tangguh dan mudah dikembangkan secara berkelanjutan.
