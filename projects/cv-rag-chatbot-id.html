Chatbot RAG CV

Chatbot Retrieval-Augmented Generation interaktif yang menjawab berbagai pertanyaan seputar latar belakang profesional saya, didukung oleh LangChain dan FAISS.

Masalah

Profil GitHub tidak menampilkan keseluruhan portofolio teknis. Sebagian besar karya utama saya terikat NDA, sedangkan CV statis memiliki keterbatasan dalam menjawab pertanyaan lanjutan secara dinamis. Saya memerlukan media interaktif bagi recruiter maupun calon klien untuk mengeksplorasi latar belakang profesional saya secara mendalam dan memperoleh jawaban presisi sesuai konteks.

Proyek ini juga berperan sebagai demonstrasi langsung arsitektur RAG yang membuktikan kapabilitas saya dalam merancang, mengevaluasi, dan men-deploy aplikasi LLM siap pakai.

Mengapa Ini Sulit

  • Kualitas retrieval menentukan hasil akhir: Apabila komponen retriever mengambil potongan teks (chunks) yang tidak relevan, LLM berisiko mengalami halusinasi. Oleh karena itu, saya mengadopsi RAGAS untuk mengukur tingkat kesetiaan data (faithfulness), relevansi jawaban (answer relevancy), dan presisi konteks (context precision), serta terus mengoptimalkan strategi pemotongan teks dan model embedding.
  • Strategi chunking yang presisi: Format CV tersusun sangat terstruktur. Pemotongan teks secara konvensional berpotensi merusak koherensi semantik. Saya mengimplementasikan strategi chunking berbasis konteks dokumen (section-aware) yang menjaga keutuhan informasi.
  • Pengembangan berbasis evaluasi (Evaluation-Driven Development): Memastikan performa chatbot tidak dilakukan dengan reka-reka, melainkan melalui penyusunan pipeline evaluasi RAGAS menggunakan kueri pengujian sintetis. Setiap penyesuaian pada alur pemotongan teks, instruksi prompt, maupun mekanisme retrieval terpantau secara terukur.
  • Optimasi deployment pada Streamlit Cloud: Pemanfaatan infrastruktur tanpa biaya memerlukan penanganan khusus terhadap tantangan cold start dan batas alokasi memori, sehingga ukuran indeks FAISS dan proses pemuatan model dioptimalkan sepenuhnya.

Tech Stack

  • LangChain LCEL: Penyusunan alur pemuatan dokumen, pemotongan teks (splitting), retrieval, dan pengelolaan prompt secara deklaratif.
  • FAISS: Penyimpanan vektor untuk pencarian semantik berkecepatan tinggi atas dokumen CV dan deskripsi proyek.
  • FastEmbed (ONNX): Model embedding lokal tanpa ketergantungan API eksternal yang mempercepat waktu boot.
  • Groq + Llama 3.3: Eksekusi penulisan jawaban memanfaatkan API inferensi Groq yang sangat cepat.
  • Streamlit: Framework antarmuka pengguna yang di-deploy di Streamlit Community Cloud.
  • RAGAS: Framework evaluasi kuantitatif untuk mengukur faithfulness, answer relevancy, dan context precision.

Apa yang Akan Saya Lakukan Berbeda

  • Menerapkan hybrid search (BM25 + semantik): Pencarian berbasis semantik murni terkadang melewatkan kecocokan kata kunci yang spesifik (exact match). Kombinasi hybrid search akan meningkatkan recall kueri seputar istilah teknologi.
  • Mengimplementasikan kueri otomatis (query rewriting): Pertanyaan dari pengguna kerap kali bersifat umum. Mengubah format pertanyaan menjadi kueri yang lebih spesifik sebelum proses pencarian akan meningkatkan presisi konteks.
  • Menampilkan referensi sumber pada antarmuka: Menyajikan rujukan asal dokumen untuk tiap jawaban akan memperkuat kredibilitas informasi yang disajikan.
  • Mengeksplorasi penggunaan reranking: Penerapan cross-encoder reranker setelah pencarian awal dapat meningkatkan presisi konteks, terutama pada pertanyaan yang bersifat kompleks.

Pelajaran Utama

Membangun chatbot RAG tergolong sederhana, namun menghadirkan chatbot yang akurat dan dapat diandalkan adalah tantangan utamanya. Kuncinya terletak pada alur evaluasi: mengukur kualitas retrieval, menyempurnakan strategi chunking, dan memastikan transparansi saat sistem tidak menemukan informasi. RAGAS menjadikan alur evaluasi ini terukur secara obyektif.
